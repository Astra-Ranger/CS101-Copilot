# 计算机科学导论：网络思维——连通性与协议栈原理

## [Page 1-2] 网络思维进阶导引
网络思维的核心在于理解多节点如何通过连通性（Connectivity）建立关联，以及如何通过协议栈（Protocol Stack）实现高效通信。

### 核心探讨提纲
*   **连通性**：研究节点的命名空间与拓扑结构。
*   **协议栈**：探究分组交换机制与互联网多层协议体系。
*   **Web 架构**：分析 Web over Internet 的层级支撑。


## [Page 3] 实体关联的图论建模：以学术合作网为例
网络思维擅长将现实世界中的复杂关系抽象为图（Graph）。
*   **节点 (Vertices)**：如学者个人。
*   **边 (Edges)**：如合著论文的关系。
*   **价值**：通过构建合著关系网，可以清晰地识别学术共同体的结构与协作模式。


## [Page 4] 连通性基础：图论描述 $ G = \langle V, E \rangle $
连通性是网络存在的物理或逻辑前提。
*   **无向图**：边仅表示关联（如好友关系）。
*   **有向图**：边表示方向性（如网页超链接、社交关注）。
*   **核心问题**：如何命名节点？如何通过拓扑结构寻找特定路径？


## [Page 5-12] 命名与名字空间 (Naming & Namespace)
名字是网络中指代实体的合规字符串。

### 1. 核心概念辨析
*   **名字 (Name)**：最广义的代称。
*   **地址 (Address)**：可直接用于定位与访问实体的名字（如内存地址、房间号）。
*   **标识符 (ID)**：在特定范围内唯一标识实体的名字（如身份证号、MAC 地址）。

### 2. 名字空间的三个衡量维度
*   **唯一性 (Uniqueness)**：一个名字是否仅对应一个节点。
*   **用户友好性 (Friendliness)**：是否易于人类理解（域名优于 IP 地址）。
*   **自主性 (Autonomy)**：用户是否可以自行创建或修改（如微信 ID 优于身份证号）。


## [Page 13-14] 互联网名字转换：DNS 与 IP 地址
互联网节点拥有多重名字空间，其核心转换机制是 DNS。

### 1. IP 地址演进
*   **IPv4**：32 比特，4 字段点分十进制格式。
*   **IPv6**：128 比特，8 字段冒号十六进制格式（解决地址枯竭问题）。

### 2. 域名系统 (DNS)
DNS 负责将人类友好的域名（如 `www.gbu.edu.cn`）转换为机器可识别的 IP 地址。


## [Page 15-17] 万维网网址 (URL) 的分层结构
URL 是资源的全局统一定位符：
`协议 (Scheme) :// 网站 (Host) / 路径 (Path)`
*   **协议名**：决定通信规则（http, https, ftp）。
*   **域名层级**：从顶级域名（.cn, .org）向下递归分支。


## [Page 18-21] 网络拓扑的三种演态
*   **静态网络**：节点与边固定不变。
*   **动态网络**：节点固定，边动态切换（如总线或交换机实现的互联）。
*   **演化网络**：节点与边随时间不断增删（如互联网、万维网）。


## [Page 22] 协议栈：支持多层抽象的通信模型
互联网采用五层协议栈模型实现无缝通信。

| 层次 | 核心协议 | 功能描述 |
|---|---|---|
| **应用层** | HTTP | 定义浏览器与服务器间的数据交换格式。 |
| **传输层** | TCP | 确保数据包在两个主机间可靠传输。 |
| **网络层** | IP | 负责数据包在复杂互联网环境中的路由转发。 |
| **链路层** | Ethernet / WiFi | 在直接相连的硬件设备间传输帧。 |
| **物理层** | 电/光/波 | 提供物理信道，传输原始比特流信号。 |


## [Page 23-29] 通信机制：线路交换 vs 分组交换

### 1. 线路交换 (Circuit Switching)
*   **特点**：独占物理路径，质量稳定但资源利用率极低（约 2%）。

### 2. 分组交换 (Packet Switching)
*   **特点**：消息被拆分为“包”（Packet），多个用户的包在同一线路上分时交错传输。
*   **优势**：极大地提升了线路吞吐量，降低了平均响应延迟，有效避免了长任务对短任务的阻塞。


## [Page 30-31] 数据包的解剖：包头与包体
每个数据包都由**包头 (Header)** 与 **包体 (Body)** 组成。

*   **包体 (Payload)**：承载的实际有效数据。
*   **包头 (Metadata)**：包含源/目的地址、查错信息（如 CRC）及其他控制字段。
*   **硬件差异**：WiFi 帧（802.11）由于无线环境的复杂性，其包头通常比以太网帧（802.3）更复杂，包含更多的管理与查错信息。
