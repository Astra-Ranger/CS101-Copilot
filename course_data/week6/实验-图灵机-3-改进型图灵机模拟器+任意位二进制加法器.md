## [Page 1-2] 程序健壮性导引：从理想运行到错误处理
上周实现的初版模拟器仅能在“理想状态”下运行。本周实验的核心目标是提升程序的健壮性（Robustness），学习如何通过异常处理机制应对非预期输入，并实现能够处理任意位宽的二进制加法器。

### 核心实验目标
1.  **健壮性优化**：为模拟器添加输入校验、重复构象检测与执行步数限制。
2.  **异常机制应用**：掌握 Python 的 `try...except` 与 `raise` 语法。
3.  **算法挑战**：设计能够处理变长二进制输入的加法图灵机。

## [Page 3-6] 理想模拟器的局限与边界情况
一个仅支持“理想输入”的程序在现实中是脆弱的。

### 常见的潜在错误
*   **输入不合规**：如缺失字段、移动方向非法（非 `L/R`）。
*   **逻辑冲突**：重复定义相同构象的转移规则。
*   **定义域缺失**：图灵机运行到了未定义转移规则的构象状态。
*   **后果**：程序可能“静默失败”（Fail Silently）导致结果错误，或抛出 Traceback 导致崩溃。

## [Page 7-15] Python 错误处理：从状态返回到异常机制

### 1. 简单状态返回法
通过约定返回值（如 `return result, True/False`）来传递错误。
*   **缺点**：导致调用链中充斥着大量的 `if not ok` 判断，代码冗余。

### 2. 异常处理机制 (`try...except`)
Python 推荐的优雅处理方式。
*   **立即停止 + 跳转**：一旦发生异常，程序立即停止当前逻辑，寻找匹配的 `except` 块。
*   **主动抛错 (`raise`)**：当检测到非法逻辑（如移动方向非 `L/R`）时，主动使用 `raise Exception('错误提示')` 终止执行并提供诊断信息。

## [Page 16-20] 模拟器组件改进：输入验证与构象匹配

### 1. 规则读取验证 (`read_table`)
在读取每一行规则时进行严格校验：
*   **格式校验**：确保每行为五元组。
*   **方向校验**：仅允许 `L` 或 `R`。
*   **重复检测**：通过 `if config in table` 判断是否已存在相同构象的规则，防止静默覆盖。

### 2. 执行期验证 (`simulate`)
在每次状态转移前，验证当前构象是否存在于规则库中。若缺失，应抛出异常提示“缺少转移规则”。

## [Page 21-23] 停机控制与资源管理
根据图灵机的不可判定性，我们无法预知程序是否会陷入死循环。

### 1. 步数限制 (`max_steps`)
为了避免无意义的资源消耗，必须为人为引入执行限制。
*   **逻辑**：当 `steps > max_steps` 时，判定图灵机无法在该输入下停机。

### 2. 模块化重构
遵循“一个函数只做一件事”原则，将模拟执行逻辑与纸带输出逻辑分离。`simulate` 函数应返回 `(tape, steps)`，由调用方决定如何展示。

## [Page 24-26] 纸带初始化与模拟器完整架构
对于任意位加法，读写头的移动范围可能远超初始输入。
*   **初始化策略**：建议采用 `["B"] * padding + list(raw) + ["B"] * padding`，其中 `padding` 可根据 `max_steps` 动态调整或设定一个合理的安全边界（如 1000）。

## [Page 27-28] 实验任务：实现任意位二进制加法器
设计一个支持变长二进制加法的图灵机规则集。

### 格式要求
*   **输入**：`(若干位 0/1) + (若干位 0/1) =`（无前导 0）。
*   **输出**：结果不应含前导 0，紧随 `=` 号右侧，并以 `B` 结尾。
*   **挑战**：需要设计一套灵活的进位与位对齐机制，使图灵机能处理不同长度的操作数相加。
