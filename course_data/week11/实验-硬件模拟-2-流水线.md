## [Page 4-5] 指令集架构（ISA）：软硬件交互的契约
ISA 规定了程序员（或编译器）如何使用硬件，它实现了架构设计与具体物理实现的分离。

### ISA 核心规约
*   **指令系统**：规定支持的操作（算术、访存、控制流）。
*   **存储架构**：定义寄存器与内存的组织方式。
*   **寻址模式**：规定如何定位数据。
*   **数据类型**：定义操作数的基本单位。

## [Page 6] 斐波那契计算机（FCA）存储架构：寄存器
为了弥补内存访问速度慢的问题，FCA 设计了高速存储器——寄存器。

### FCA 寄存器组
1.  **通用寄存器 (GPR)**：`R0, R1, R2, R3`（用于临时存放 64 位操作数）。
2.  **程序计数器 (PC)**：存储下一条要执行指令的内存地址。
3.  **标志寄存器 (FLAGS)**：存储比较指令（CMP）的布尔结果。

<!-- Page 7-9 -->
## [Page 7-9] FCA 存储架构：内存组织与字长
内存是存储程序和海量数据的核心部件。

### 核心约定
*   **字节寻址**：8 比特为一个字节，是存储的最小单位。
*   **操作数单位**：8 字节为一个“字”（Word），FCA 指令以字为单位进行处理。
*   **小端法存储 (Little-Endian)**：多字节数据的**低字节**存放在内存的**低地址**处。

## [Page 10-11] 寻址模式与数据类型

### 1. 复杂寻址模式
FCA 支持“基址-变址-比例-位移”寻址：
*   公式：$ \text{Address} = \text{Base} (R0) + \text{Index} (R2) \times \text{Scale} + \text{Displacement} $

### 2. 数据类型
FCA 仅支持 **64 比特二进制补码整数**。所有的运算（ADD）与访存（MOVR）均以该字长为单位。

## [Page 13-16] 硬件实现：指令生命周期与 CPU 结构
处理器的运行是一个周而复始的周期过程。

### 指令周期的三个阶段
1.  **取指 (IF)**：从内存获取 64 位机器指令并存入指令寄存器（IR）。
2.  **译码 (ID)**：将 IR 中的指令解析为硬件部件可识别的控制信号。
3.  **执行 (EX)**：根据控制信号驱动 ALU 或内存完成具体运算与写回。

<!-- Page 17 -->
## [Page 17] 三级流水线（Three-Stage Pipeline）设计
流水线技术通过让不同指令在同一时刻处于不同的执行阶段，极大地提高了处理器的吞吐量。

### 流水线并发示意
*   **T0**：指令 1 进行 IF。
*   **T1**：指令 1 进行 ID，指令 2 进行 IF。
*   **T2**：指令 1 进行 EX，指令 2 进行 ID，指令 3 进行 IF。

## [Page 25-32] 流水线核心逻辑模拟

### 1. 流水线寄存器
IF 阶段与 ID 阶段、ID 阶段与 EX 阶段之间通过“流水线寄存器”传递指令、操作码及操作数。

### 2. 译码逻辑（ID）
需要根据指令格式（R 型、M 型、C 型等）提取 `opcode`、`register`、`immediate`。
*   **关键辅助函数**：`sign_ext`（符号扩展），用于将指令中的短位宽补码扩展为 Python 的 64 位整数。

### 3. 执行逻辑（EX）
根据译码出的操作码，修改寄存器文件 `self.reg` 或调用 `self.mem.store_word` 修改内存。

## [Page 33-35] 流水线驱动与周期更新
处理器的 `run` 循环不断调用各阶段逻辑并触发时钟。

```python
def run(self):
    while self.is_running:
        self.instruction_fetch()
        self.instruction_decode()
        self.execute()
        self.tick() # 驱动所有 FlipFlop 更新状态并增加 PC
```
